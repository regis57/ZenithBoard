# Social sharing

Off by default. Switched on, the Pi posts the aircraft worth a post — a military tanker, a Beluga, a type it has not seen in a month — to **Bluesky**, as a picture with a short text. Two looks for the picture, both drawn by the Pi itself in a second or two, on a Pi 3B included, with no browser:

| Look | What it shows |
|---|---|
| `dots` (default) | The dot-matrix wall as it is at that moment, and in the right-hand column the aircraft's track over the last minutes, drawn in the same dots |
| `flap` | The split-flap board, beside a map with the aircraft's track. The map can be a plain map, a dark one, satellite, terrain, or none |

```bash
sudo zenithboard social setup      # the Bluesky account, the words, the picture   (or: menu -> 4 Settings -> 6 Social sharing)
sudo zenithboard social test       # draw the picture, print the text, post nothing
sudo zenithboard social on         # from now on, under the rules you chose
```

Why Bluesky alone: X closed its free API in February 2026 and charges per post; Threads and Instagram cannot take an uploaded picture, they fetch it from a public address, which would mean putting the Pi on the internet. Bluesky takes the picture directly, costs nothing, and its API is open. Mastodon was supported in 0.18 and taken out in 0.19.0; an update removes its token from the Pi (revoke it on your instance too). See [When a provider changes something](Providers) for the general attitude.

## Step by step

### 1. Create the account, and its app password

The Pi never gets your real password. Bluesky has a secret made for one program, which you can revoke without changing anything else.

Create the account at bsky.app. Then *Settings → Privacy and Security → App Passwords → Add App Password*. Name it `zenithboard`. The password is shown **once**, in the form `xxxx-xxxx-xxxx-xxxx`: copy it. The wizard asks for your handle (`yourname.bsky.social`, without `@`) and that app password.

**Declare the account as automated, before the first post.** This is what keeps an account like this one from being reported and suspended as an undeclared bot: *Settings → Account → Automation label* (*Étiquette d'automatisation*), switch it on (Bluesky 1.119, March 2026). It puts a `bot` self-label on the profile, and a badge shows beside the name on the profile and on every post. Bluesky's developer guidance asks bot accounts to do exactly this.

Say it in the bio as well, in plain words — the badge means nothing to someone who does not know it — and say that the texts are templates, not generated by AI, so nobody has to guess which kind of automated account it is.

Revoking: delete the app password on Bluesky. The Pi's posts stop with the next attempt, and `zenithboard social check` says so.

### 2. Run the wizard

```bash
sudo zenithboard social setup
```

Give the handle and paste the app password (typed blind, as a password); the wizard **tries the account before going further** and stops if Bluesky refuses it. Then it asks for the words:

| Question | What it is for | Default |
|---|---|---|
| Where is this? | The place named at the end of the posts. Your words: a town name (`Trémery`) reads *above Trémery*, words that start with their own preposition (`near Metz`, `over the Moselle`) are kept. The receiver's position is never used. A small village narrows your home down to a few kilometres; a city, a department or a region does not | nothing |
| Sharing radius | An aircraft is a candidate while inside it. Separate from the wall's radius | 15 km |
| Minimum minutes between posts | So the account is not a firehose | 120 |
| What is worth a post | See the rules below | rare, military, helicopter, heavy, farthest |

And then for the picture:

| Question | Choices | Default |
|---|---|---|
| The look | `dots` or `flap` | `dots` |
| The colour of the letters and the track | the wall's own colour, or amber, green, red, white, turquoise, blue — the wall's colours, read from its own style sheet | the wall's |
| The map (flap only) | `normal`, `night`, `satellite`, `terrain`, `none` | `normal` |

Each of these has its own command too, for a quick change: `social words`, `social picture` (the three picture questions), `social look dots|flap`, `social colour green|wall`, `social map satellite`.

### 3. Try it

```bash
sudo zenithboard social test
```

Waits up to half a minute for an aircraft with a track, draws the picture, and prints the text and the alt text. **Nothing is posted, ever, by `test`.** It always finds something to show (it adds the `all` rule for itself), so it also says plainly whether the service, under *your* rules, would post that aircraft — and if not, why not. The picture is at `http://PI-ADDRESS:8080/social/preview`, on your home network like the wall. `social test 4071f1` does it for one aircraft by its hex code.

**Post now** (menu, or `sudo zenithboard social post`) is different: it posts the aircraft it finds at once, whatever the rules and the gap. Use it to see a real post; the service itself waits for an aircraft your rules pick. A post made by hand counts for the service like its own: the gap starts again from it, and that aircraft is not posted twice.

### 4. Switch it on

```bash
sudo zenithboard social on
zenithboard social status
zenithboard logs social
```

`on` installs what the picture needs from Debian if it is missing — Node (about 30 MB; it draws the dot-matrix picture and formats the rows of both), plus Pillow with the DejaVu fonts for the split-flap one (a few MB) — starts the service, and says the rules it will follow. `off` stops it and keeps the account; `remove` forgets the account too.

## The picture

### Dot-matrix

![The dot-matrix picture](https://github.com/regis57/ZenithBoard/raw/main/docs/images/social-dots.png)

The wall's rows as the tablet shows them (`FLT  ETD11K`, `REG  A6-APD`, then airline, type, altitude, speed, route), with two differences: the time on the last row with its offset from GMT as the Pi's time zone has it that day (`11:39 GMT+2` in a French summer, `GMT+1` in winter), where the tablet shows the distance and direction; and, in the right-hand column, the track where the tablet has the silhouette and the photo.

**Reading the track column.** North is up. The aircraft is the arrow in the middle, pointing where it flies; the dimmer dots behind it are where it was. Under them, a legend read as a key:

| Line | Means |
|---|---|
| a piece of the dim trail, then `10MIN` | the trail shows the last ten minutes |
| a bar with end ticks, then `20KM` | that bar is twenty kilometres on the track's scale |

The scale is chosen for each picture, from 1 to 500 km per bar, the smallest that keeps the whole track inside the frame. The flags are the wall's: the country of the registration, then the maker's.

### Split-flap with a map

![The split-flap picture, normal map](https://github.com/regis57/ZenithBoard/raw/main/docs/images/social-flap.jpg)

The board as the wall's split-flap look draws it — the same nine rows, without the flags, fourteen letters wide instead of sixteen so the map gets the room — beside a map centred on the track. On the map: the track and the aircraft in the picture's colour, edged in black so they read on any background; a key in the corner (`LAST 10 MIN`, and a scale bar in km or miles); north; and the map's credit along the bottom.

| Map | What it is | Credit, on the picture and in the post |
|---|---|---|
| `normal` | OpenStreetMap, rendered by EOX | © OpenStreetMap contributors, EOX maps.eox.at |
| `night` | The same, darkened on the Pi | the same |
| `satellite` | Sentinel-2 cloudless 2025 by EOX, with EOX's labels | EOxCloudless 2025 by EOX, cloudless.eox.at, Copernicus Sentinel data; labels © OpenStreetMap contributors |
| `terrain` | EOX's terrain rendering, with its labels | © OpenStreetMap contributors and others, EOX maps.eox.at |
| `none` | No map: the track on black, over a faint grid. Nothing is fetched | none |

**Where the map comes from, and why there.** The tiles come from [EOX::Maps](https://maps.eox.at), whose layers are free to use with attribution and a link back; every post carries both, as a clickable link. OpenStreetMap's own tile servers are not used: their [usage policy](https://operations.osmfoundation.org/policies/tiles/) rules out automated fetching that nobody is looking at, which is what a service posting by itself does. The satellite layer is licensed CC BY-NC-SA 4.0: free for a hobby account like this one, **not for commercial use**, and a picture made with it is shared under the same licence. The Pi asks only for the few tiles under the picture, names itself in every request, and keeps them for a month under its state folder, so the tiles over your area are fetched once, not at every post. If the tile service does not answer, the picture is drawn with no map and no credit, and `social test` says so.

## What gets posted, and what never does

**The rules.** An aircraft is a candidate while inside the sharing radius (except a range record, below), known (a type, a registration or an airline — an aircraft with nothing known is never posted), airborne, with at least thirty seconds of track, and not already posted — an aircraft is posted once: never again while the receiver still sees it, nor for a day after it has gone. Among the candidates, the rules say which are worth it:

| Rule | Posts an aircraft that is… |
|---|---|
| `rare` | of a type that at most two *other* aircraft have flown in the last thirty days. Counted per aircraft, not per look |
| `military` | military, by the decoder's database flag or by its type |
| `helicopter` | a helicopter |
| `heavy` | an A380, 747, Beluga, Antonov 124/225, C-5, C-17, A400M, or any four-engined airliner |
| `farthest` | a new range record: farther than anything in the last thirty days, and over 50 km. Looked for in the whole sky, not only inside the sharing radius |
| `all` | everything that flies over, the special aircraft included: ticking `all` is ticking every line. When several are there at once, the special one goes first; otherwise the best-known aircraft of the moment. One post per gap, as always. (Called `any` before 0.19.1; the old word still works) |

`rare` and `farthest` judge against history, so they wait until the service has watched for **three days**; `zenithboard social status` says where it stands. The other rules work from the first minute.

Several rules can match; the best candidate is the one matching the most, and knowing the most (route, airline, model each count). One post per gap, at most.

**The text.** Says what the wall knows, in English, and nothing it does not. It starts with the flight and ends with the place you gave (here `Trémery`); the altitude is said as one (*altitude 8 500 m*) so it never reads as a distance from the place; an airline callsign is a hashtag, so the flight can be followed:

| Case | Text |
|---|---|
| Airline flight, route known | `Flight Etihad #ETD11K · Airbus A380-800 · Paris → Abu Dhabi · altitude 8 500 m · above Trémery` |
| Airline flight, route unknown | `Flight British Airways #BAW123 · Airbus A380-800 · altitude 11 900 m · above Trémery` |
| Callsign, no airline known | `Flight #BGA113J · Airbus A330-743 Beluga XL · F-GXLH · altitude 9 750 m · above Trémery` |
| Registration only | `Aircraft D-EABC · Cessna 172 · altitude 910 m · above Trémery` |
| Helicopter | `Helicopter D-HABC · Airbus Helicopters H145 · altitude 460 m · above Trémery` |
| Military | `Military flight #RCH123 · Boeing KC-135R Stratotanker · altitude 7 620 m · above Trémery` |
| Range record | `Flight Emirates #UAE201 · Boeing 777-300ER · … · altitude 11 280 m · range record for 30 days: over 300 km out, seen from Trémery` |
| Nothing known | no post |

The registration is said when no airline is: an airline flight is known by its callsign, and the registration is on the picture. A range record ends with *seen from* rather than *above*: it was nowhere near overhead. When the picture has a map, the map's credit follows on its own line. Then the hashtags (`#ADSB #avgeek #ZenithBoard` by default; `#helicopter` or `#military` replace `#avgeek` when they apply). The picture carries an alt text built from the same facts, for screen readers, with the map's full credit. Units follow the wall's setting.

**What never leaves the Pi:**

* **The receiver's position**, and anything that gives it away: the posts carry no bearing and no distance — a range record says *over 300 km*, rounded down to 50, which tells the record and draws no useful circle — the picture's last row shows the time where the tablet shows `12KM NE`, and the track, on dots or on a map, is centred on the aircraft with nothing marking the receiver. A hundred posts give nothing to triangulate. The map's tiles are asked for by the Pi, from your connection, like any map you would open.
* **The Planespotters photo.** Their terms forbid re-hosting it. The track takes its place.
* **The secret.** It lives in `/etc/zenithboard/social.env`, owned by root, readable by the `zenithboard` group (the service's user), mode 0640; never in `config.env`, never in a log, never in `zenithboard config`. `zenithboard security` checks the file's owner and mode.
* **The picture itself**, after the post: it is drawn in `/run/zenithboard/social` — memory, not the card — and deleted once Bluesky has answered, whether it took it or not.

## How it works

`zenithboard-social.service` runs `flightinfo/social.py` as the `zenithboard` user inside the same sandbox as the wall (exposure at most 1.5 on systemd's scale; `tests/test_units.sh` holds the ceiling). Every five seconds it reads the decoder's `aircraft.json` and keeps the last fifteen minutes of positions per aircraft in memory. Every fifteen seconds it asks the wall itself, on the loopback, which aircraft are inside the sharing radius — with everything the wall knows about them: airline, model, route, flags. When a candidate passes the rules and the gap has passed, it draws the picture and posts it.

The dot-matrix picture is `tools/social-render.js`: Node reads `app.js` and lifts the wall's own text functions (the way the tests do), draws the rows, the flags from `flags.js`, the track in the right-hand column, and writes a PNG with Node's `zlib`; the colours come from the wall's `style.css`. About 60 KB. The split-flap picture asks the same script for the board's rows (`--lines`, the wall's own formatting) and paints them with Pillow in `flightinfo/social_card.py`, with the map tiles and the track; a JPEG of about 500 KB, under Bluesky's limit of 1,000,000 bytes (the quality steps down if a picture would not be).

Bluesky is three requests, standard library only: `createSession → uploadBlob → createRecord`, with the hashtags and the map's link as facets so they are clickable, and the alt text and the aspect ratio with the image.

State lives in `/var/lib/zenithboard/social/state.json`: for each type, the last few distinct aircraft seen and the day (for `rare`), the farthest aircraft of each of the last thirty days (for `farthest`), the day the service started watching, which aircraft were posted in the last day, and the last post's time. The map tiles are cached next to it, in `tiles/`, at most 60 MB and a month. Once an hour the service writes one line to its journal — how many looks, how many found a candidate, when the next post is possible — so `zenithboard logs social` answers *why no post?* `social remove` deletes it all.

## Updating and removing

`sudo zenithboard update` carries the service like every other: the unit file is refreshed and the service restarted when sharing is on. The secret is untouched by an update — except a Mastodon token left from 0.18, which the update removes.

```bash
sudo zenithboard social off       # stop posting; account kept
sudo zenithboard social remove    # account, state, map tiles and service gone (Node and Pillow stay: apt remove nodejs python3-pil)
```

## Troubleshooting

| What you see | What to do |
|---|---|
| `social check` says FAILED | The handle has no `@`, and the password is the *app* password, not the account's. Make a new app password if in doubt |
| `social test` says nothing to show | No aircraft with thirty seconds of track inside the sharing radius right now. Try a wider radius, or `social test HEX` with an aircraft from `zenithboard status` |
| It posts nothing | First: `test` never posts. Then `zenithboard social status` — is it *on*, is the account ready, is the gap still running? Then `zenithboard logs social`: the hourly line says how many looks found a candidate. `rare` and `farthest` start after three days, so on the first days only `military`, `helicopter` and `heavy` can fire: tick `all` to see it post the ordinary traffic too (the special aircraft still go first) |
| A post went out, but not by the service | *Post now* posts at once, whatever the rules. The service's own posts show in `zenithboard logs social` as `posted …` |
| The split-flap picture has no map | The Pi could not reach `tiles.maps.eox.at` (no internet, or the service busy: EOX limits heavy load). `social test` says so; the next picture tries again. `social map none` stops asking |
| `zenithboard logs social` shows `the wall did not answer` | The wall server is down: `zenithboard status`, `zenithboard logs flightinfo` |
| A post went out that you would rather not have | Delete it on Bluesky. Narrow the rules with `social words`. Nothing posted can be recalled by the Pi |
